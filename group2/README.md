## Цель работы

Построить воспроизводимый конвейер данных для e-commerce платформы, в котором каждая СУБД решает отдельную задачу:

* PostgreSQL используется как транзакционное OLTP-ядро;
* ClickHouse используется для аналитики и агрегаций;
* ManticoreSearch используется для полнотекстового поиска по отзывам;
* Python ETL синхронизирует данные между системами;
* Grafana отображает состояние баз данных и конвейера.

## Выбранный вариант реализации

Для синхронизации используется batch ETL на Python.


## Архитектура

```text
                         PostgreSQL
                      OLTP и master data
                              |
                     Python batch ETL
                     /               \
                    v                 v
        ClickHouse 2x2           ManticoreSearch
        OLAP и аналитика         поиск по отзывам
                    \                 /
                     \               /
                            Grafana
```

ClickHouse-кластер включает:

* 2 шарда;
* 2 реплики в каждом шарде;
* 3 узла ClickHouse Keeper.

## Часть 3. ClickHouse — OLAP-хранилище

ClickHouse используется для хранения денормализованных данных о заказах и выполнения аналитических запросов.

* 3 узла ClickHouse Keeper.

```text

```

### Денормализованная таблица

Для аналитики создана локальная таблица:

```text
ecommerce.orders_analytics_local
```

Она содержит:

* дату заказа;
* идентификатор заказа;
* имя клиента;
* регион;
* название товара;
* категорию;
* количество;
* цену;
* сумму позиции;
* статус заказа.

Таблица использует движок:

```sql
ReplicatedMergeTree
```

Партиционирование выполняется по месяцу заказа:

```sql
PARTITION BY toYYYYMM(order_date)
```

Ключ сортировки:

```sql
ORDER BY (
    category,
    order_date,
    order_id
)
```

Поверх локальных таблиц создана распределённая таблица:

```text
ecommerce.orders_analytics_distributed
```

Ключом шардирования выбран:

```sql
cityHash64(order_id)
```

Благодаря этому все позиции одного заказа направляются на один шард.

### ETL PostgreSQL → ClickHouse

Перенос данных выполняется скриптом:

```text
etl/pg_to_ch.py
```

ETL выполняет следующие действия:

1. создаёт ClickHouse-таблицы и materialized view;
2. очищает результаты предыдущего запуска;
3. выполняет JOIN таблиц PostgreSQL;
4. экспортирует результат в CSV;
5. загружает CSV в `orders_analytics_distributed`;
6. синхронизирует реплики;
7. выполняет аналитические запросы.

Результаты ETL сохранены в:

```text
checks/etl_sync.txt
```

Результаты аналитики сохранены в:


### RT-индекс reviews

Создан RT-индекс:

```sql
CREATE TABLE reviews (
    title       text,
    body        text,
    product_id  integer,
    customer_id integer,
    rating      integer,
    created_at  timestamp
)
morphology='stem_enru'
min_word_len='2';
```

Поля `title` и `body` являются полнотекстовыми.

Поля:

* `product_id`;
* `customer_id`;
* `rating`;
* `created_at`;

используются как атрибуты для фильтрации.

Настройка:

```text
morphology = stem_enru
```

включает английский и русский стемминг.

```sql
SELECT
    id,
    title,
    rating,
    WEIGHT() AS weight
FROM reviews
WHERE MATCH('брак сломался возврат')
ORDER BY weight DESC
LIMIT 10;
```

Найдены отзывы с заголовком:

```text
Проблема с товаром
```

Рейтинг найденных документов составляет `1` или `2`.

Значение релевантности:

```text
WEIGHT() = 1540
```

Время выполнения:

```text
0.0134 sec
```

### Вывод

ManticoreSearch используется как специализированный поисковый слой.

Он позволяет:

* выполнять полнотекстовый поиск на русском языке;
* ранжировать документы через `WEIGHT()`;
* совмещать поиск с фильтрацией по атрибутам;
* строить фасеты;
* быстро находить положительные и негативные отзывы.

PostgreSQL остаётся основной системой хранения отзывов, а ManticoreSearch содержит их поисковое представление.
